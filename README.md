# Кто выгуливает Бориса

Учебный Node.js micro-MVP для вымышленной компании «Догяндекс». Сотрудники записываются на прогулку с офисным псом Борисом и видят последнюю отметку о кормлении.

## Что реализовано

### Прогулки

- На странице показана текущая дата и пять фиксированных слотов: `09:00`, `11:00`, `13:00`, `15:00`, `17:00`.
- Свободный слот можно занять, указав непустое ФИО. Лишние пробелы по краям удаляются.
- Занятый слот показывает ФИО сотрудника и не содержит формы повторной записи.
- Сервер атомарно бронирует только свободный слот. Повторная или одновременная попытка записи получает понятный конфликт и не меняет первоначальную запись.
- Брони сохраняются в SQLite и остаются после перезагрузки страницы и перезапуска приложения.

### Кормление

- Карточка «Последнее кормление» показывает ФИО и время последней отметки.
- Если отметок ещё нет, страница сообщает об этом.
- Можно добавить новую отметку с непустым ФИО; каждая отметка сохраняется в SQLite, а карточка сразу обновляется.

## Технологии

- Node.js и встроенный HTTP-сервер;
- встроенный модуль `node:sqlite` и SQLite-файл `data/boris.sqlite`;
- HTML, CSS и браузерный JavaScript без фреймворков и внешних зависимостей.

## Локальный запуск

Нужен Node.js с поддержкой встроенного модуля `node:sqlite`.

```bash
npm start
```

Откройте в браузере [http://localhost:3000](http://localhost:3000). При первом запуске приложение создаст SQLite-файл и пять свободных слотов для текущей даты.

Если порт `3000` уже занят, остановите процесс, который его использует, или запустите приложение на другом порту:

```bash
PORT=3001 npm start
```

## Проверка основных сценариев

Используйте только синтетические данные, например «Анна Тестова» и «Илья Примеров».

1. Откройте страницу и убедитесь, что показаны текущая дата и ровно пять слотов.
2. Введите синтетическое ФИО в свободном слоте и нажмите «Записаться».
3. Убедитесь, что слот стал занятым и показывает введённое ФИО.
4. Во второй вкладке попробуйте занять тот же слот другим синтетическим ФИО: должен появиться отказ, а исходное ФИО не изменится.
5. Обновите страницу или перезапустите приложение и проверьте, что запись сохранилась.
6. В блоке «Последнее кормление» укажите синтетическое ФИО и нажмите «Отметить кормление»; карточка должна показать это ФИО и время.
7. Откройте страницу в узком окне браузера и повторите сценарий записи.

## Ограничения

Это учебный micro-MVP. В нём нет авторизации, ролей, отмены записи, календаря на неделю, уведомлений, истории в интерфейсе, интеграций, деплоя и production-grade эксплуатации. Доступны только пять слотов на текущую дату и отображение последнего кормления.

Карточка кейса: «Кто выгуливает Бориса»

Разработать простое веб-приложение для сотрудников компании «Догяндекс», которое помогает организовать прогулки и кормление офисной собаки Бориса.

Приложение должно показывать свободное время для прогулок, позволять сотрудникам записываться и сохранять информацию о последнем кормлении.

• Chrome — ручное тестирование приложения.

• Добавлена защита от повторного бронирования занятого времени.
• Настроено сохранение информации в SQLite.
• Реализован учёт последнего кормления.
• Создан интерфейс для компьютера и мобильного экрана.

Создан работающий локальный прототип приложения.

В ходе ручного тестирования подтверждено, что записи на прогулки и кормления сохраняются после обновления страницы. Проверена работа в обычном окне Chrome и в режиме инкогнито, а также отображение на узком экране.

Ключевая итерация работы с ИИ

Задача для Codex: реализовать запись сотрудников на прогулку с Борисом по пяти временным слотам с сохранением данных в SQLite.

Что получилось: Codex создал серверную логику, интерфейс записи и подключил базу данных.

Что потребовалось исправить: при первоначальной проверке запись не сохранялась — после нажатия кнопки слот оставался свободным. После дополнительной итерации с Codex ошибка была устранена.

Как я проверила результат: вручную записала сотрудника на прогулку, убедилась, что слот стал занятым, проверила сохранение записи и работу формы.

Вывод: ИИ помог быстро реализовать функциональность, но результат потребовал ручного тестирования и исправления обнаруженной ошибки.

## Следующий инженерный шаг

Следующим шагом я бы добавила автоматизированный тест основного сценария записи на прогулку.

Сейчас приложение проверено вручную. Автоматический тест позволит убедиться, что свободный слот бронируется, повторная запись отклоняется, а данные сохраняются в SQLite.

Я выбрала этот шаг, потому что надёжность бронирования — главное требование проекта. Такой тест поможет безопасно вносить изменения, не добавляя лишних функций.
